### 1.2 格式（已完全跑通）

```
PXET 图集: 'PXET'; i64@0x14=纹理数; u32@0x34=PMAN偏移; u32@0x3C=纹理表偏移
纹理表条目: 12 字节 (flag, len, blobOff)
   ★ PMAN 条目按 hash 排序，与纹理表下标不同序 —— 必须用条目里的 texIndex 反查名字
记录: [BE32 解压后大小][BE32 压缩后大小][负载]
   压缩后 == 0                -> 负载即明文
   否则                        -> LZSS 流
   ⚠ 压缩后 可能大于实际负载（60000016 即如此）-> 必须按可用长度钳制，否则越界
LZSS: 4KB 窗口, 窗口指针初值 4078, 12bit 偏移, 4bit 长度+3, 控制位 LSB-first
TDXT: 64 字节头; u32@0x0C=总长; u16@0x10=宽; u16@0x12=高;
      fmt = tdxt[0x14]（当 u32LE@0x08 == 0x00010100）否则 tdxt[0x17]; 像素自 0x40
   fmt: 0x01 灰度 / 0x0B 565 / 0x0E BGR888 / 0x10 BGRA8888 / 0x11 4bit索引+调色板
        0x13 A1R5G5B5 / 0x15 ARGB / 0x16 DXT1 / 0x18 DXT3 / 0x1A DXT5
        0x1F A4R4G4B4 / 0x20 BGRA
```

## 2. ★ 命名与尺寸真相（解码后才确定）

以已知正常曲 `90000014` 为准：

| 贴图名 | 尺寸 | 真实含义 |
|---|---|---|
| `BNR_BIG_ID<id>` | **320×320** | 大曲绘（游玩界面右上缩略图） |
| `BNR_ID<id>` | **160×160** | 曲绘（选曲界面小曲绘） |
| `IDX_ID<id>` | **324×40** | **曲名/艺人文本条（宽）** |
| `IDX_MINI_ID<id>` | **160×24** | **曲名文本条（小）** ← 选曲格子里那行字 |

**结论：`music_info.xml` 里根本没有标题字段（`name_string` 只是五十音排序用假名读音），
「曲名」是预先渲染成贴图的** —— 所以「没有曲名」和「没有曲绘」是同一类问题：贴图取不到。
