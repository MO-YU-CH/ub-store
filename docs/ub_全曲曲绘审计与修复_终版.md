## 1. 先纠正一个根本误解：「曲名」不是文本，而是画在大曲绘里的

- `contents/data/music_info/music_info.xml`（官方 base，1,514,918 B，1108 条）**没有任何标题/艺人字段**；
  overlay `music_omni.xml`（1612 条）同样没有。
- 唯一的字符串字段 `name_string` 是**五十音排序用的假名读音**，不是显示标题：

  | 曲 | 实际显示 | `name_string` 解码 |
  |---|---|---|
  | 90000014 | Dream drip macchiato | トリイムトリツフマキアアト |
  | 11000168 | CRAZY ARTS | クレイシイアアツ |

- `data/font/` 里全是真实 TTF/TTC，但**没有标题来源**。

**结论：jubeat 的「曲名 + 艺人名」是绘制在大横幅贴图里的（`BNR_BIG_ID<id>`，格式 `7F TDXT`）。**
所以用户说的「没有显示曲名和选曲界面的小曲绘」是**同一类问题：贴图找不到**。

### 贴图命名总表（实测）

| 贴图名 | 所在图集 | 用途 |
|---|---|---|
| `BNR_BIG_ID<id>` | **单曲图集** `tex_l44_bnr_big_id<id>.bin` | 大横幅（画着曲名+艺人名）／游玩界面右上缩略图 |
| `BNR_ID<id>` | 分组图集 `tex_l44??_bnr_j_<grp>_<n>.bin` | 横幅层（layer `bnr_id10000000.png`） |
| `IDX_ID<id>` | 分组图集 | 中号曲绘 |
| `IDX_MINI_ID<id>` | 分组图集 | 选曲界面小曲绘（layer `idx_mini_id10000000.png`） |

## 2. 真正的根因：**分组图集必须放进 mod 目录才会被加载**

判定手段：游戏日志 `M:layeredfs: Using ./data_mods/omnimix/…` **只记录命中 mod 目录的文件**，
因此它是「游戏实际打开了哪些图集」的唯一可靠观测点。

**决定性证据（本轮）**：把 97 个分组图集复制进 mod 目录后重启，
开机一次性加载的分组图集 **13 → 55 个**：

| 时点 | 开机加载的分组图集 |
|---|---|
| 修复前 | 仅 mod 目录里已有的 13 个（11 个合并图集 + `om_001` + `om_002`） |
| 修复后 | **55 个**：`11_001`~`11_018`、`09_002`~`09_027`、`01_001`~`08_001`、`05_001/002`、`06_001`、`07_001` … 全部加载 |

→ 只放在 base 目录 `data/d3/model/` 的同名图集**不会被加载**，其所有贴图查找必然失败
（`W:aep: texname error [BNR_ID…]`，画面呈现空白/纯白方块）。

这也解释了此前的现象：12:32 把 11 个分组图集放进 mod 目录后，
`90000176 / 60000086 / 11000113` 立刻恢复；而其它曲目依然缺失。
