## 〇〇.2 PXET 容器格式与名字 hash（读通容器，hash 未破）

### 判决性实验：hash 是名字的纯函数

拿 **0730 版与当前版的同一张图集** `tex_l44av_bnr_j_11_016.bin` 比对同名条目的 hash：  
**同名 9 个，hash 全部相同（9/9），0 个不同** ⇒ hash 只由名字决定；  
且**表是按 hash 升序排列** ⇒ 它极可能就是**查找键**。

正确的 (名字, hash) 对应（此前配错过，已修正）：

```
BNR_ID11000150 0xEA797B28   BNR_ID11001007 0xEAFB7110   BNR_ID11001008 0xEAFB712C   BNR_ID11001009 0xEAFB710C
IDX_ID11000150 0xB07227A9   IDX_ID11001007 0xB0F02D91   IDX_ID11001008 0xB0F02DAD   IDX_ID11001009 0xB0F02D8D
IDX_MINI_ID11000150 0xA2C38871  IDX_MINI_ID11001007 0xA2418249  IDX_MINI_ID11001008 0xA2418275  ...009 0xA2418255
```

### 容器布局（`tex_l44av_bnr_j_11_016.bin`，341,288 B）

```
0x00-0x3F  PXET 头：0x0C=文件大小  0x14=纹理数(12)  0x1C=纹理数据区起始(0x244)
                    0x34=PMAN偏移(0x40)  0x3C=PMAN区大小(0x1B4)
0x40-0x1F3 PMAN：0x44=内容大小(0x174)  0x50=条目数(12)
            条目 @0x5C 每条 12B = (u32 hash, u32 纹理索引, u32 名字偏移[相对 0x40])
            名字明文，区域末尾 **有 64 B 余量**
0x1F4-0x243 另一张 (size,offset,0) 12B 记录表（指向文件尾部的小 blob）
0x244-     纹理数据（LZ 压缩 DXT）
```

### 结论：**无法为"新名字"造条目**

hash 算法（Konami 私有）没能反推。已排除：crc32 全部标准参数集 / CRC32C / CRC32D / JAMCRC / MPEG2 / BZIP2 / POSIX、  
fnv1 / fnv1a、djb2、sdbm、java31、移位旋转族（`h<<k ^/+`、rotl/rotr）、`h*K+c` 乘加族（K=2…8191）、  
UTF-16LE/BE、字符串反序、各种填充（8–48 字节、NUL/空格/0xFF）。  
对数据做了结构分析：同一字节改动在不同前缀下 XOR 差恒定 ⇒ 每个字节位置的映射固定，但映射本身未知。

**能改名字（原地等长替换），不能加名字（算不出 hash）。**

### 因此对「把 39[2] 的美术复制给 39」的执行情况

**修法**：往覆盖层的 `allomni.bin` 追加 2 条登记（486 → 488），**不动基础文件**：

```
('L44_BNR_BIG_ID90000048', 'tex_l44_bnr_big_id90000048.bin', 'mdl_l44_bnr_big_id90000048.bin')
('L44_BNR_BIG_ID11001007', 'tex_l44_bnr_big_id11001007.bin', 'mdl_l44_bnr_big_id11001007.bin')
```
