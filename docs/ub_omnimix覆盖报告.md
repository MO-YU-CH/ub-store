# ★★ 追加改造：让 `ub.exe` 直接就是 omnimix 模式（2026-10-04 收尾）

用户说明「我原本是用 ub.exe 启动游戏的」。实测 `ub.exe` 拉起的命令行是：

```
"D://JUBEAT//contents//spice.exe"  jubeat.dll        ← 原版参数，不带任何 mod 开关
```

照原样用 ub.exe 启动时，SpiceTools **自带的 layeredfs** 确实会自动挂载 `./data_mods/omnimix`：

```
M:layeredfs: IFS layeredFS v1.9-SPICE init...
M:layeredfs: Detected mod folders:
M:layeredfs: ./data_mods/omnimix
```

——但那只是「文件覆盖」。omnimix 真正让它多出几百首歌的是 `omnimix.dll` 里那几个内存补丁
（`music_omni patch` / `music_db limit patch 1~4` / `omnilist patch` / `bnr-hook`），
这些在 ub.exe 的原版命令行下**不会加载**（日志里没有 `I:omnimix:` 那行）。

## 解决办法：让 omnimix.dll 直接顶替 jubeat.dll

先确认了 PE 导入表：**只有 `omnimix.dll` 一个模块 import `jubeat.dll`**，其它 DLL 都不依赖它，
所以这个互换是安全的。

做三件事：
1. 街机上把原来的 `jubeat.dll`（真游戏，3,276,440 B）另存为 **`jb_org.dll`**
2. 把 `omnimix.dll` 里的 **4 处 `jubeat.dll` 字面量全部等长替换成 `jb_org.dll`**
   （含导入表里那处 + `GetModuleHandle("jubeat.dll")` / `GetModuleInformation("jubeat.dll")` 用的字符串；
    `jubeat.dll` 与 `jb_org.dll` 都是 10 字符，原地等长替换不会破坏 PE 结构）
3. 改造后的模块上传为 `contents\jubeat.dll`

于是 ub.exe 那条**没改一个字的**原版命令行：
```
spice.exe  jubeat.dll
```
实际加载的就是 omnimix 模块，由它再把真游戏（`jb_org.dll`）拉起来并打补丁。
