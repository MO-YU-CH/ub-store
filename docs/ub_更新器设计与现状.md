# jubeat 更新器 ub_updater — 设计与现状

> 依据：本地 6 个更新包（`<GAME_DIR>\L44JF_*.7z`）与已解开的 5 个包目录（`tmp\packs\`）**实测**得出，非推测。

---

## 一、问题

官方更新包里有**两类「删除标记」文件**，会把我们已恢复/补齐的曲目打回空白：

| 标记 | 形态 | 危害 |
|---|---|---|
| `<music_id>_msc.ifs` | **144 字节**（空谱面桩） | 覆盖**谱面** → 该曲变空谱 |
| `tex_l44_bnr_big_id<id>.bin` | **1 字节**（空贴图桩） | 覆盖**大曲绘** → 该曲无图 |

> ⚠️ 注意：60 字节的 `mdl_*.bin` 是**正常**模型元数据，**不能**当标记跳过（很容易误判）

实测标记清单（本地 6 个包）：

| 包 | 144B 谱面桩 | 1B 贴图桩 | 受影响曲目 |
|---|---|---|---|
| 20240325from2024021400 | 1（`90000083_msc.ifs`） | 1（`id90000083`） | 90000083 |
| 20240918from20240730 | 3 | 4 | 11000113 / 60000086 / 90000031 / 90000034 |
| 20241127from20240918 | 2 | 2 | 11001007 / 90000048 |

## 二、已实现并实测通过（`tools/ub_updater.py`）

```
python tools/ub_updater.py scan  --pack <7z|目录> [--json]
python tools/ub_updater.py apply --pack <7z|目录> --game <游戏目录> [--dry-run] [--allow-delete]
```

**能力**
1. **读包**：支持 `.7z`（py7zr，**无需密码**）与已解开目录；自动剥掉包内顶层同名目录
2. **标记识别**：`_msc.ifs ≤1024B`、`tex_*.bin ≤16B` 判为桩；`mdl_*.bin`(60B) 明确非标记
3. **安全应用**：默认**跳过全部删除标记**；写入前对每个被覆盖文件做**时间戳备份**；落在 `tmp/ub_updater/backup/<时间戳>/`
4. **受保护曲目报告**：从标记文件名反解出受影响 music_id 列表
5. **dry-run**：只出计划不写盘
6. **留痕**：每次 apply 写 `last_apply_<时间戳>.json`（应用/跳过/备份清单）
7. **temp 不落 C 盘**：工作目录固定 `<PROJECT_ROOT>\tmp\ub_updater\`

**测试记录（真实包，dry-run）**
```
L44JF_2024091800from2024073000 → 将写入 37 / 跳过标记 7 → 受保护 [11000113, 60000086, 90000031, 90000034]
L44JF_2024112700from2024091800 → 将写入 97 / 跳过标记 4 → 受保护 [11001007, 90000048]
```
> 测试中发现并修复 1 个真 bug：解压目录跨包复用，导致第二个包挑到第一个包的解压结果（表现为「源缺失 101」）。已改为**每包独立解压目录** + 完成标记。

## 三、尚待实现（「自动添加歌曲」的后续链路）

`apply` 目前**只做安全落盘**。要让新曲真正出现在选曲列表，还需按顺序补上：

| # | 步骤 | 可复用的现成实现 |
|---|---|---|
| 1 | **曲表合并**：把包内 `data/music_info/music_info.xml` 的新曲并入 overlay `data_mods/omnimix/music_info/music_omni.xml` | 今天做 1612 条合并时的脚本与字段规则 |
| 2 | **包表注册**：把新曲的贴图/谱面包名写进 `allomni.bin` / `alldata.bin`（`alldata.bin` 包内有现成新版，可直接用；`allomni.bin` 需增量追加） | `omnisrc/merge_pxet.py`、`Tlkp`（包表读写） |
| 3 | **贴图落位**：新曲的 `tex_l44_bnr_big_id<id>.bin` 等按 today 的规则放好（**单曲图集保持官方原样，不改写**） | 今日「铁律」：只补分组图集、不改写单曲图集 |
| 4 | **去重检查**：新曲与已有曲的 id/读音重复检测（今天已发现 12 组多 id 重复） | `ub_曲目重复问题诊断.md` |
| 5 | **DLL 处理（重要）**：包内 `modules/jubeat.dll`（真游戏新版）会覆盖；需要重新把 omnimix 挂载模块放到 `jubeat.dll`、新版真游戏存为 `jb_org.dll`，**并重新打 4 个补丁**（补丁偏移随版本变化，必须按新版本重新定位） | `locate_sites.py` / `patch_jb_org.py` |
| 6 | **回滚**：一键回滚到本次更新前状态 | 已有时间戳备份，补一个 `rollback` 子命令即可 |

---

## 四、风险提示（务必知悉）

1. **补丁重定位**：更新包里的 `jubeat.dll` 是新版本，4 个补丁的**偏移会变**，直接套用旧偏移会把 DLL 打坏。每次更新后必须重新定位并验证反汇编。
2. **`music_db.dll`**：包内也带（143,000 B）。它决定选曲列表，覆盖后需确认不会把 omnimix 的曲目清单行为改掉。
3. **`prop/bootstrap.xml`、`achievement_info/*`**：包内会覆盖，属正常更新内容，需保留。
4. 每次更新前**先整目录备份**（或至少备份 `data_mods/`、`jb_org.dll`、`dev/nvram/`）。
