## 2. ★ 真正的失败原因：我把单曲图集「改胖」反而弄坏了它

日志实锤（14:16 / 14:26，用户浏览时）：

```
15:16:42 layeredfs: Using ./data_mods/omnimix/d3/model/tex_l44_bnr_big_id90000059.bin
14:16:41 W:aep: texname error [BNR_BIG_ID90000059]      ← 文件打开了，名字就在里面，却报找不到
```

```
15:26:50 layeredfs: Using ./…/tex_l44_bnr_big_id90001023.bin
14:26:49 W:aep: texname error [BNR_BIG_ID90001023]
```

| 文件 | 结构 | 游戏表现 |
|---|---|---|
| `tex_l44_bnr_big_id90000016.bin`（**base 原版**，1 张贴图） | 原始 | ✅ 正常 |
| `tex_l44_bnr_big_id90000059.bin`（**我重建**，4 张贴图） | PMAN 4 条、hash 升序、名字齐全、偏移连续 | ❌ 打开后仍报找不到 |

我逐字节对比过 PMAN 头（`clen/f8/fc/f14/f18` 与原始完全一致）、hash 值（从原文件继承）、名字表、纹理表偏移 —— **结构自洽但游戏查不到**。
说明 `tex_l44_bnr_big_id*` 这类**单曲图集对内部结构有严格要求，被我改写后就失效了**。

→ **这就是「之前的修复都没有生效」的原因**：我此前把 795 首的单曲图集重写成多贴图版并覆盖上去，
反而把它们从「可用」变成了「不可用」。

## 4. 唯一剩下的 1 个名字：`BNR_BIG_ID90000048`

- base 的 `tex_l44_bnr_big_id90000048.bin` 里装的其实是 **`BNR_BIG_ID11001007`**；
- 2025 包同名文件内容相同（大小一致）；
- 全机台 base 的名录里**没有** `BNR_BIG_ID90000048`。

→ 这是 **asset-id 别名**现象（文件名用 music_id，里面的贴图名是另一个 id）。
官方 base 本身就没有 `BNR_BIG_ID90000048` 这个名字，属官方数据如此，非我造成。

## 5. 结论与后续

- ✅ **不再改写单曲图集**（这是唯一有效的原则：单曲图集必须保持官方原样）。
- ✅ 额外贴图统一靠**把分组图集放进 mod 目录**解决（这一机制已被反复验证有效）。
- 待你实机复核：`90000016`、`90000059`、`90001023`、`11001007`、`50000360`、`60001011`。
