# 曲目重复问题诊断（2026-10-05）

## 现象
部分歌曲在选曲列表里出现**两次**：
- **fly above**：谱面 / 曲绘 / 曲目信息**完全相同**，一个带 PICK UP、一个不带
- **千本樱**：**曲绘不同**，其它相同

## 诊断：同一首歌被登记成两个不同 music_id

| 曲 | id A | id B |
|---|---|---|
| fly above | `11000030`　ver=`c000`（当前版本 → 所以带 **PICK UP**） | `90000216`　ver=`2000`（旧版本 → 不带） |
| 千本樱 | `50000020`　ver=`3f00` | `80000037`　ver=`3000` |

- `version` 是**版本位掩码**（3fff/3ff0/3fc0/3f00/3e00/3c00/3800/3000/2000/8000/c000 都是位组合）。
  位掩码命中当前版本 → 游戏标 **PICK UP**；旧 id 不命中 → 不标。**这正好解释你看到的现象**。
- 两个 id 不同 → 引擎按 id 取贴图 → **曲绘不同**（千本樱就是这种）。
- 谱面/曲目信息相同 → 因为 omnimix 那边的 `_msc.ifs` 与字段是同一份内容。

## 责任归属（重要）：**大部分不是我改出来的**

与「今天动手前的最早备份」`music_omni.xml.bak_20261004_1930`（1420 条原始 omnimix）对比：

| 组 | 原始 omnimix 是否已含两个 id |
|---|---|
| カアニハル / サンキユウ / **千本樱** / テンコクトシコク / ノイ / ハイスクウルラフ / ハラノイア / ヒイロオ / フロミス / マイヒイロオ（**10 组**） | **都已含** → 属 omnimix 固有 |
| **fly above**（`11000030`+`90000216`） | 两个都没 → **外来（后加）** |
| リントシテサクハナノコトク（`11000076`） | 只有 `10000068` → `11000076` 是**后加** |

进一步查官方包 `L44-013-2025020500`（最新官方 2025-02-05 版）的 `music_info.xml`：

- **`70000042` 与 `80000014`（ハラノイア）两个都在官方包里**（ver=f800 / ver=f000）
  → **Konami 自己的数据就有多 id 重复**，正常情况靠**曲目清单 `music_db.dll`** 决定只列出一个。
- `50000020`（千本樱旧 id）、`30000052`、`30000002` 等则**不在**官方 0205 包中 → 来自 omnimix/旧版本包。

## 建议的修法（待确认后执行）

| 方案 | 做法 | 影响面 |
|---|---|---|
| **A. 删掉「我后加」的 2 个 id** | 从 `music_omni.xml` 移除 `90000216`（fly above 旧 id）与 `11000076` | 安全、可控，**推荐先做** |
| **B. 隐藏而非删除** | 把多余 id 的 `version` 位掩码清零（不属于任何版本 → 不该出现） | 需实机验证，可能影响包引用 |
| **C. 处理 omnimix 固有的 10 组** | 需先确认它们在**原始 omnimix 环境**下是否也重复（若是，则属已知现象，可按同一规则清理） | 面较大，建议逐个核对两 id 的曲绘/谱面后再删 |
| **D. 不动曲表，改 `music_db`** | 让游戏清单只列出新 id | 需要改 `music_db.dll`（143,000 B），风险最高 |

**共同风险**：若某个 id 被 `music_db`/包/其它曲目引用（例如 HOLD 谱的 `parent_id`），删掉对应 `music_info` 记录可能引发异常 —— 因此每删一个 id 都要**检查是否有 `parent_id` 指向它**，并实机验证。
