## 5. ✅ 推荐方案：增量叠加（不删任何文件）

### 5.1 上传清单

**A. 38 个新增文件** → 全部按原路径放进 `<ARCADE_ROOT>\`（纯新增，无副作用）

**B. 7 个安全变更文件**：

**C. 明确排除（14 个）**：
- 6 个 `_msc.ifs` 空壳 + 4 个 `tex_l44_bnr_big_id*` 空壳 → **保住 6 首被删曲**
- 3 个「只删不加」的缩小图集 → **保住被删曲的小曲绘**
- `tex_l44_bnr_big_id90000048.bin` → **保住我们修好的 39 大曲绘**

**D. 完全不碰**：`modules/**`（2 个）、`prop/**`（4 个）、`data_mods/**`、`dev/nvram/**`

### 5.2 配套：包表登记（不覆盖 `alldata.bin` 的更稳做法）

`allomni.bin`（覆盖层包表，488 条）在运行时会**替掉**官方 `alldata.bin`，所以新曲要能被加载，必须往 `allomni.bin` 里补记录。做法：

1. 从官方 0205 的 `alldata.bin` 里**读出**新曲/新图集对应的记录（`(pack名, tex文件, mdl文件)` 三元组）：
   - `L44_BNR_BIG_ID11000152/166/167/168/169/174`
   - `L44AV_BNR_J_11_017/018/019/020`、`L44AV_LCS_J_11_019`
2. 用现成工具（`omnisrc/fix_bigbanner_reg.py` 同款逻辑）把这些记录**追加**进 `data_mods/omnimix/d3/package/allomni.bin`（保持按 hash 升序、条目数自增）。
3. 这样**不需要动官方 `alldata.bin`**，被删曲的登记也不会被注销 —— 比覆盖 `alldata.bin` 更安全。

### 5.3 曲目表合并

把 6 首新曲按包内官方字段（`parent_id / version / bpm / level_* / detail_level_* / name_string / pos_index / index_start / step / color1 / music_type / genre / grouping_category`）追加进覆盖层 `music_omni.xml`：

**1,589 条 → 1,595 条**

## 8. 附：本次核验用的方法

1. 版本识别：对比 `prop/ea3-ident.xml` 的 `<ext>`（街机 2024021400 / 包 2025020500）。
2. 全量文件清单：街机 `Get-ChildItem -Recurse` → CSV（11,834 行）。
3. **全量 MD5**：街机侧用 `[System.Security.Cryptography.MD5]::Create()` 逐文件算 `data/` 的 MD5（10,184 个 / 11 GB，耗时 2 分 26 秒），与本地包内 9,604 个文件比对 → 得出 9,545 完全相同、1 同尺寸异内容、20 变更、38 新增、618 街机独有。
4. 图集内容：解析 PXET 的 PMAN 名字表，逐个确认新曲小曲绘归属、以及 3 个缩小图集是「只删不加」。
5. 曲目表字段：解析官方 `music_info.xml` 的 `<data>` 块，取全字段。
